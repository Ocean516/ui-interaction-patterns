# 界面交互技巧

把用户的自然语言需求变成符合产品目标的交互，按需采用参考中的六种模式。一次只采用解决当前问题的模式；六种效果不是必选清单。

## 执行顺序

1. 先读项目约束、现有界面、组件、导航与状态管理。找出用户要完成的任务、当前阻碍、应该保留的操作习惯。已有参考视频或截图时，先看实际内容，再提取机制，不照搬画风、文案或品牌素材。
2. 用中文简短说明所选模式和它解决的问题。能从项目判断的常规选择直接完成；只有结果取决于缺失的关键需求时才提问。
3. 读取 [六种交互模式](references/six-patterns.md) 中对应部分，复用已有框架和组件实现。修改现有界面时保留业务规则、权限、数据格式与导航约定。
4. 覆盖交互的打开、关闭、选中、空态、加载、失败和长内容等实际需要的状态。保持键盘、触屏和屏幕阅读器可用，并遵守系统减少动态效果设置。
5. 运行项目并检查具体用户路径；现有测试可用时运行相关检查。不要为纯视觉微调机械增加测试。无法运行时明确说明验证范围，不把代码检查称作交互验证。
6. 用简短中文交付：改了什么、用户如何使用、实际验证结果和仍存在的限制。

## 与其他能力配合

- 当前需求需要完整的视觉设计时，配合已安装的 UI 设计技能（例如 design-ui 或 frontend-design），由其负责视觉方向；本技能负责交互细节。不要为了同一件事叠加多个相似技能。
- 浏览器实际操作和检查选用已安装的浏览器技能。发布网站、写入 GitHub 或设计平台使用对应工具和现有授权。
- 用户只需要成品时直接修改目标项目；没有目标项目且目标是保存能力时交付技能包，不擅自创建演示网站。
- 本技能不调用逆向工具、不安装无关插件，也不绕过权限。自动选择技能不等于自动获得发布、付费或删除权限。

## 自然语言触发示例

- “让这个日历的空白日期也能直接添加记录。”
- “选中不同分类时，上面的标题和说明一起变化。”
- “这个底部弹层太割裂了，让它跟页面融为一体。”
- “首页做成图片和标题一起滑动的卡片。”
- “用户头像太占空间，帮我处理得紧凑一点。”
- “底栏的加号点完就进入编辑，少走一步。”

不要因为用户说“优化界面”就强行使用某种效果；先定位实际交互问题，必要时仅使用通用 UI 设计技能。
